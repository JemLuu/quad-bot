# Reconciliation — planned vs actual

How to judge a check-in and frame proposals. Keep it grounded in the athlete's actual data and goal.

## Compare
- **Volume:** planned weekly distance/time vs actual (from activity-log Weekly totals).
- **Key sessions:** were the long run and quality sessions done, modified, or missed?
- **Trend:** is volume rising/holding/falling vs the plan over the last few weeks?

## Adherence verdict
Pick one and say why:
- **On-track** — hitting volume and key sessions within a reasonable margin (~±10%).
- **Ahead** — consistently exceeding plan (watch for doing too much too soon).
- **Behind** — missing volume or key sessions, but recoverable with small tweaks.
- **At-risk** — repeated misses, or the trend threatens the goal/health.

## Always cross-check the health log
Before proposing more load, read `health-log.md` Active issues. A missed week due to injury → propose *recovery/modification*, not catch-up. Flag if the pattern of misses looks injury-driven and suggest `/physical-therapist`.

## Framing proposals
- Make each proposal **specific, small, and independent** so the user can accept some and reject others.
- Give each a **one-line reason** tied to the data ("you missed Tue/Thu, so…").
- Prefer adjusting the *upcoming* week(s); don't try to make up missed work by piling it on (raises injury risk).
- Common moves: scale a week's volume, shift a session to a free day, swap a quality session for easy, push the long run, insert a down week, or hold the current week and reassess.
- If the gap is structural (goal date no longer realistic, fitness far off track), say so plainly and recommend `/training-plan` for a redesign rather than patching.

## Accept/deny UX
Offer exactly: **accept all / reject all / pick by number**, and allow the user to edit a proposal before accepting. Apply only what's accepted, then confirm what changed.
